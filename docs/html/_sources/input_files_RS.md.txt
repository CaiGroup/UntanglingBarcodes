# Input Files For the Reed-Solomon Encoded experiment processing workfow

Input files are placed in the resources folder. the raw images are too large to include in a git repository, so they will have to be retrieved from Zenodo.

Within the resources folder, create a new folder named codebooks (dapi_alignment_workflow/resources/codebooks) 

## Codebooks

The resourses/codebooks folder contains

* full_RS_q11_k7_half_pool_cb.csv - the codebook table that lists the genes probed and their codewords as well as the negative control codewords. The first column, gene_name, contains the gene symbol or negative control. The remaining columns: Block1, Block2, Block3, Block4, ..., and Block10 give the pseudocolors in their respective blocks encoding the gene (or negative control) of that row. A block with pseudocolor 0 does not probe/readout barcodes encoding this codeword in a seqFISH experiment.
* RS_q11_k7_H.csv - is the [parity check matrix]. The matrix contained in this file matrix muliplied with any codeword vector listed in the above codebook will produce a 0 vector.


The workflow will automatically generate codebooks containing negative control (off-target) codewords as well. The parameters section describes how you may set the number of negative control codewords to use.

## Data

Within the resources folder, create a new folder named data (dapi_alignment_workflow/resources/raw_images). Alternatively, you may place a symlink named data that links to a folder somewhere else in your file system as long as the other folder is organized as described below. This can be useful since seqFISH datasets are large and you may wish to store them together in one place without making copies. You can make such a symlink by navigating to the resources folder, then running the linux command

<pre> <code> ln -s path data </code> </pre>

or windows command (while running as administrator)

<pre> <code> mklink /d path data </code> </pre>

where path is the path to the other data folder in your file system.

Place your data in the data folder.

Data folders should include folders for each hybridization cycle:

HybCycle_1, HybCycle_2, ... , HybCycle_N

Hybridization cycle folders should contain image stacks generated by micromanager that follow the naming convention:

MMStack_Pos\<i\>.ome.tif

where \<i\> is the integer position number of the image.

Initial background images for each position should be in a folder resources/data/initial_background/ where micromanager generated image stacks follow the same naming convetion as for those in HybCycle folders.

Segmentaion results should be in a folder named resources/Labeled_Images

Segmentated labeled images are tiffs following the same naming convention as above for each position. Background pixels are labeled as 0, pixels for each cell are assigned a positive integer value denoting the cell identification number for that cell in that position. Labeled images should be aligned with the initial background image.
