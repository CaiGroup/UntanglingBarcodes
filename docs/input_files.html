Input Files

Codebooks

2019 SeqFISH+ Experiment

The codebook folder contains codebook CSV files that contain and columns: gene, Block1, Block2, Block3, Block4, …, BlockN listing only encoded genes in the codebooks folder. Each row will have the list the name of the gene encoded, and the pseudocolor (1 to the number of pseudocolors) that encodes it in each barcoding round.

The 2019 seqFISH+ experiment contained 3 parallel experiments- one in each channel- so it includes 3 codebooks with filename channel_<laser_wavelength>.csv

channel_488.csv channel_561.csv channel_643.csv

The laser wavelength is given the same as recorded the metadata of the ome.tif files saved by micromanager in the experiment.

The codebook folder also includes a tab delimited file containing the [parity check matrix] in resources/codebooks/H.txt. The matrix product of any codeword in your codebook and the [parity check matrix] should be zero. For this dataset we use the parity check matrix of the original seqFISH+ paper:

 1 1 -1 -1

The workflow will automatically generate codebooks containing negative control codewords as well. The parameters section describes how you may set the number of negative control codewords to use.

Reed-Solomon Encoded experiment

The resourses/codebooks folder contains

  • full_RS_q11_k7_half_pool_cb.csv - the codebook table that lists the genes probed and their codewords as well as the negative control codewords. The first column, gene, contains the gene symbol or negative control. The remaining columns: Block1, Block2, Block3, Block4, …, and Block10 give the pseudocolors in their respective blocks encoding the gene (or negative control) of that row. A block with pseudocolor 0 does not probe/readout barcodes encoding this codeword in a seqFISH experiment.

  • RS_q11_k7_H.csv - is the [parity check matrix]. The matrix contained in this file matrix muliplied with any codeword vector listed in the above codebook will produce a 0 vector.

  • block_pseudocolor_table.csv - is a table with columns “block”, “pseudocolor”, “channel”, and “readout hyb”.

Check out the readme in this folder and the contents of its subdirectories for instructions on how to generate these files for new experiments

Data

2019 SeqFISH+ Experiment

Input files are placed in the resources folder. the raw images are too large to include in a git repository, so they will have to be retrieved from Zenodo.

Within the resources folder, create a new folder named data (Disentangling_SeqFISHplus/resources/raw_images). Alternatively, you may place a symlink named data that links to a folder somewhere else in your file system as long as the other folder is organized as described below. This can be useful since seqFISH datasets are large and you may wish to store them together in one place without making copies. You can make such a symlink by navigating to the resources folder, then running the linux command

  ln -s path data

or windows command (while running as administrator)

  mklink /d path data

where path is the path to the other data folder in your file system.

Place your data in the data folder.

Data folders should include folders for each hybridization cycle:

HybCycle_1, HybCycle_2, … , HybCycle_N

Hybridization cycle folders should contain image stacks generated by micromanager that follow the naming convention:

MMStack_Pos<i>.ome.tif

where <i> is the integer position number of the image.

Initial background images for each position should be in a folder resources/data/initial_background/ where micromanager generated image stacks follow the same naming convetion as for those in HybCycle folders.

Segmentaion results should be in a folder named resources/Labeled_Images

Segmentated labeled images are tiffs following the same naming convention as above for each position. Background pixels are labeled as 0, pixels for each cell are assigned a positive integer value denoting the cell identification number for that cell in that position. Labeled images should be aligned with the initial background image.

Reed-Solomon Encoded experiment

The raw image stacks for this experiment are too large to fit in a zenodo repository. Instead, we include the much smaller preprocessed images in the results/ims_bg_sub folder and the fit fiducial marker locations in the results/fm_fits folder of this repository.

Labeled images giving the locations of each cell in the reference image are in the resources/labeled_images folder. Background pixels are labeled as 0, pixels for each cell are assigned a positive integer value denoting the cell identification number for that cell in that position.
